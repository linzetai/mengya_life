# MengYa 0.19.1 · 对话能力入口与可发现性修正

基线 `0.19-morrow`；本包 `0.19.1-morrow` / versionCode 27。数据库不变（v16）。

## 一、删除「+」入口

- 输入框左侧「＋」按钮及其单项悬浮菜单已移除；不再出现淡紫色悬浮方块。
- 输入框恢复为整行聊天输入 + 发送按钮，横向空间回收。
- 底部不再有任何常驻快捷功能条。
- 视觉沿用绿色系、圆角、字号与间距，无新增面板。

### 原「整理为目标草案」的能力去向

审计确认它不是简单重复：原按钮调用 `proposalMode`，让模型把**整段讨论整理成多节点目标计划**（含 assumptions / risks，最多 12 个节点），这是自然语言单目标提取（0.18 的 GOAL 提案）未覆盖的能力。

处理方式：**删除按钮，但把意图接入自然语言**。

- 用户说「把刚才聊的内容整理成目标草案 / 生成目标草案 / 整理成目标」时，`send()` 直接把这句话走原 `proposalMode`，复用同一套目标草案卡片、确认与写入流程。
- 用户说「把这个计划设为目标 / 整理成一个目标 / 拆解成阶段」时，继续走 0.18 的 GOAL 提案（单目标 + 可选拆解）。
- 两条链路都只生成草稿，确认后才写入；没有第二套目标存储。

## 二、对话内轻量引导（P2）

- 当用户发了一段**较长且有计划结构**的内容（含“打算/计划/先/然后”等），且没有触发记录/目标提取时，在对话末尾出现一条对话内建议：
  「要把刚才讨论的计划整理成目标吗？」+「生成草案 / 不用了」。
- 建议属于消息流，不是固定工具栏。
- 点「不用了」后本次会话不再出现（`planSuggestionDismissed`）。
- 简单闲聊、短句、已有记录提取时不会出现。
- 成长回顾的可发现性：沿用周回顾页已有的「和顾问聊聊」，未新增常驻入口。

## 三、回顾表达（P3）

- 系统提示收紧：回顾默认 2–3 段、尽量 200 字内；事实 → 1–2 个变化（标注为观察）→ 1 条最重要建议 → 最多 1 个问题；只有用户要求详细分析时才展开。
- 强调只有一天记录不得当作整周趋势、日期不明要说明、缺失记录不补写。
