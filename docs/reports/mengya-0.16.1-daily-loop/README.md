# MengYa 0.16.1 · Daily Progress Loop

基线 `0.15.3A-morrow`（当前代码含 0.16 / 0.16A 的对话式记录与语义修正）；本包 `0.16.1-morrow` / versionCode 23。

## 1. 现状审计（先查后补）

已有并复用：
- 首页「今天」：目标列表、本周发现卡、查看全景。
- 目标详情：全景页内展开卡片（标题/状态/进展次数/子目标/进度条）。
- 记录进展：`CheckinSheet`，说明必填、数值/单位选填，`GoalRules` 校验，`saving` 防重复，`GoalRepository.addCheckin` 唯一写入口。
- 持久化：Room `goals` / `goal_checkins`，Flow 驱动首页、详情、轨迹、周回顾。
- 轨迹：真实数值曲线（按单位/语义分组），空状态与单点说明。
- 一周回顾：已生成并展示。

发现的断点（本轮修复）：
1. 从「今天」点目标只切到全景并滚动，**不展开**，用户还要再点一次才能看见「记录进展」。
2. 详情即使展开，也只显示“N 次进展”，**看不到刚保存的那条内容**。
3. 全景是独立页面，不挂在主 Scaffold 的 Snackbar 上，**保存后没有成功提示**。
4. 轨迹里的目标标题**不能点回目标**。

## 2. 本轮实现

- **自动展开目标路径**：`LifePanoramaScreen` 根据 `focusedGoalId` 计算祖先链并展开，从今天进入即见详情与「记录进展」。
- **详情显示最近进展**：`GoalDao.observeCheckinStats` 带出最后一条的说明/数值/单位，`GoalNode` 透传，展开卡片显示“最近进展 · 日期 + 内容”。
- **保存就地确认**：全景页顶部出现 `进展已记录` 确认条（2.6s 自动消失并消费消息），不再依赖主 Scaffold Snackbar；主页面仍保留原 Snackbar。
- **轨迹回到目标**：趋势块可点击，直接 `openPanorama(goalId)` 并展开。
- **单元测试**：新增“快照带出最近一条进展”测试。
- 未改目标完成状态规则（`addCheckin` 仍只把未开始置为进行中），未引入平行状态或第二数据源。

## 3. 数据流与导航

```
今天（GoalSnapshot + 本周发现）
  └─ 点目标 → openPanorama(id) → FocusGoal(id)
       └─ 全景自动展开该目标（含父级）
            ├─ 最近进展（stats 里的 lastNote/lastValue/lastUnit）
            ├─ 记录进展 → CheckinSheet
            │     ├─ 校验失败 → 行内错误，不写库
            │     ├─ 取消 → 关闭，不写库
            │     └─ 保存 → GoalRepository.addCheckin → Room
            │           → goals/checkins Flow 刷新：
            │              详情次数+最近进展、首页发现卡、轨迹、周回顾
            │           → 全景顶部「进展已记录」
            └─ 进度/状态（未开始 → 进行中，沿用既有规则）
轨迹（GoalTrends）
  └─ 点趋势块 → openPanorama(id) → 同上展开
```

## 5. 已知问题

1. 真机输入使用 ADB，只能输入英文；中文输入路径由 Compose 输入框本身保证，未在录屏中展示中文备注。
2. 全景页展开状态未持久化，重进应用后需重新展开（从今天点入会自动展开）。
3. 轨迹每页只显示最近 2–3 组，更多要在目标进展历史里看（既有设计）。
4. 保存确认条为 2.6s 自动消失，无手动关闭。
5. 断网/授权等 AI 相关失败不影响手动链路；但本轮未单独造错验证 AI 失败提示。

## 6. 下一步建议

- 目标详情做成可直达的展开态（记住上次展开）。
- 进展历史支持编辑/删除（当前只有顾问记录的修改/撤销）。
- 周回顾里把“本周新增”与“当前累计”分开陈述，复用 0.16A 语义。
- 记录成功后提供“再看一眼轨迹”的轻量跳转。
