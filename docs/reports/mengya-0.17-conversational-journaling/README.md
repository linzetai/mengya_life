# MengYa 0.17 · Conversational Journaling

基线 `0.16.1-morrow`；本包 `0.17-morrow` / versionCode 24；数据库 v15（候选表新增日记字段，不新增日记表）。

## 一、统一手动与 AI 记录语义

- 手动「记录进展」新增类型选择：**本次新增 / 当前累计 / 无数值**，默认「本次新增」。
- 与顾问共用 `ProgressKind`（delta / snapshot / none）写入同一个 `goal_checkins.amount_kind`，没有第二套模型。
- “今天读了 30 页”按本次新增记录，轨迹进入「新增」序列，不会再默认画成累计总页数。
- 旧数据保持原样：v14 之前的记录已迁移为 snapshot；本轮不重写历史。
- 只记录文字时选「无数值」，不写 metric。

## 二、对话式日记（复用 RecordProposal）

- `RecordKind` 增加 `DIARY`；草稿同样存 `record_proposals`（v15 增加 `diary_title` / `diary_body` / `diary_entry_id` / `source_message_ids_json`）。
- 正式保存只调用现有 `JournalRepository.createEntry`，写入 `journal_entries`；不存在第二套日记存储。
- 卡片支持预览、编辑（标题/正文）、保存、取消；保存后显示「打开日记」，并自动跳到日记页同一篇。
- 已保存的日记再次修改走 `JournalRepository.updateEntry`，改的是同一篇，不产生副本。
- 草稿编辑只更新草稿；是否落库仍由「保存到日记」决定；已保存日记的编辑则直接改正式内容。

### 触发与自然对话

- 明确指令（整理成日记 / 写成日记 / 记到日记…）一定提取。
- 只有“足够长且有具体事件”的叙述才考虑建议；纯情绪表达（“今天有点难过。”）只认真回应，不弹卡片。
- 提取窗口限制为最近 15 分钟，且**只使用用户自己说过的话**作为事实来源；顾问的建议不会被写成用户的反思。
- 提示词明确：不编造事件、人物、数字、日期、情绪；更早无关话题不写入。

## 三、长期上下文

- 正式日记保存后进入现有日记领域，只有它会在「日记」授权下参与顾问上下文。
- 候选草稿存在 `record_proposals`，不进入日记快照/上下文；普通聊天历史与正式日记在上下文来源里分开标注。
- 未授权「日记」时：不提取日记草稿；上下文也不读取历史日记（已有测试覆盖）。

## 五、已知问题

1. 真机 ADB 只能输入英文，录屏中的补充文字为英文；中文输入由输入框本身保证。
2. 日记提取会额外发一次模型请求，真实环境约多 5–15 秒；期间有“正在整理日记…”提示。
3. 草稿只保留标题/正文，不保留逐条消息引用（`sourceMessageIds` 已留字段，暂未填入）。
4. 日记草稿“修改”不会自动保存，需要再点「保存到日记」——这是有意设计，但比进展卡片多一步。
5. 未做“建议→拒绝”后的再次提醒抑制；取消后本轮不再出现。
6. 备份与恢复已覆盖候选表新字段的列存在性，但未在真机走完整恢复往返。
