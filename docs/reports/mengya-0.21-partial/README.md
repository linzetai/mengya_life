# MengYa 0.21 · 部分交付（P0 数据可靠性）

基线 0.20A；本包 `0.21-morrow` / versionCode 30；DB v17（表结构未变）。

## 已完成

### 备份/恢复纳入小计划
- `BackupSnapshot` 增加 `smallPlans` / `planEvents`，导出 12 张表。
- `BackupFormatV2` 编码两张表并计算 hash/counts。
- 校验器把两张表设为**可选表**：旧备份缺少时仍通过结构校验，按空表恢复；counts 缺失不误报。
- 恢复插入 `small_plans` / `plan_events`；旧备份恢复时按空数组摘要校验，不产生孤儿/重复。
- 新增测试：计划与事件导出、旧备份缺表仍可校验；**341 项通过，0 失败**。

### 写入屏障
- 小计划草稿保存不再传 `null`，改用发送链路的真实 restore generation，恢复期间仍受写保护。

### 时间语义
- 新增 `PlanTime`：以创建时刻 + 用户时区锚定今天/明天/这周/下周/周末/月底，跨周后不会把旧“这周”解释成新一周；原始原话仍保存在 `time_scope`。
- 3 项时间边界测试。

## 未完成（本轮主体）

1. **「今天」近期计划区未实现**：无 UI 改动、无截图。
2. **计划执行记录未实现**：没有“已记录 N 次”的持久结构，因此聊天里的“练了一次/两次”无法计入计划进度，也无法在完成后核对次数。
3. **P3 回复以执行为先、P4 轻量提示** 未实现。
4. 没有真实模型/真机验证、截图或录屏；没有备份恢复真机往返（只做格式/兼容单测）。
5. 计划完成仍不会自动完成关联目标（符合规则，但未写测试）。

## 结论
本轮只完成了数据可靠性前置项，未完成“今天看到计划 → 聊天记录执行 → 回顾”的主闭环，不能作为 0.21 功能交付。
