# MengYa 0.18 · Conversational Goals

基线 `0.17-morrow`；本包 `0.18-morrow` / versionCode 25；数据库 v16（候选表新增目标变更字段，不新增目标表）。

## 一、复用与约束

- GOAL 仍是 `RecordProposal` 的一种，草稿存 `record_proposals`（v16 增加 `goal_change_json` / `applied_goal_ids_json`）。
- 正式写入只经 `GoalRepository.createGoal / updateGoal`；没有第二套目标库、没有平行写入。
- 修改已有目标只调用 `updateGoal`，保留目标 id、状态、全部进展与关联；不删除重建。
- 目标提案永不自动写入，即使明确指令也必须确认。

## 二、自然语言创建目标

- 闸门：明确“设为目标 / 创建目标 / 改成 / 拆解”等；或带明确时间跨度且有具体方向（“三年内找到…”）。
- 模糊愿望（“最近有点想学吉他”）只聊天；说“帮我把学吉他设成一个目标”才生成草稿。
- 草稿包含：标题、层级、领域、截止日期、待确认项；不编造薪资、期限、阶段。
- 卡片展示标题/层级/领域/期限/不确定项，可确认创建、修改、放弃；创建后自动打开人生全景并定位新目标。

## 三、修改已有目标

- 模型必须引用已授权目标 id；客户端补齐“修改前快照”。
- 卡片明确展示“原：…”与“新：…”，只写用户要改的字段。
- 确认后走 `updateGoal`；实测把“五年内积累 50 万”改为“三年内积累 50 万”，13 次进展、子目标与轨迹全部保留。

## 四、目标拆解

- 仅当用户要求拆解或明显不知从何开始时，模型给出 2–5 条阶段建议。
- 卡片逐条勾选，只创建选中的；不强制拆解。
- 实测对“找到下一阶段的发展方向”生成 4 条阶段建议，确认后在目标下创建子目标。

## 五、来源与上下文

- 日记提案已补 `sourceMessageIds`；目标提案同样记录最近 6 条用户消息 id（15 分钟窗口）。
- 顾问只在已授权类别内读取目标/进展/日记；候选草稿不进入任何上下文。
- 提示词新增：回复简洁自然、不必长篇、不强行记录、不输出原始 Markdown（客户端另有 `stripMarkdown` 兜底）。

## 六、真机验证（QA，真实 deepseek-flash）

| 场景 | 结果 | 证据 |
|---|---|---|
| 模糊愿望 | 只聊天，无目标卡 | `01` |
| 明确长期目标（三年内换工作） | 生成创建草稿 → 确认 → 全景新增并定位 | `02`、`03`、录屏 |
| 修改已有目标期限 | 草稿显示原/新差异 → 确认后同一目标更新，13 次进展保留 | `04`、`05` |
| 目标拆解 | 4 条阶段建议可勾选 → 创建为子目标 | `06`、`07` |
| 另一个新建（学吉他） | 确认后写入「学习」并打开全景 | `08`、录屏 |
| 网络/格式失败 | 显示真实失败与重试，未写入任何目标 | `09` |
| 重启 | 目标、期限、进展、子目标均在（拆解后再次重启验证） | `05`、`08` |

录屏：`goal-create.mp4`（约 70s：聊天 → 生成“学吉他”目标草稿 → 确认 → 全景定位）。

单测：**332 项通过，0 失败**（新增目标闸门/解析/永不自动创建 6 项）。

## 七、已知限制

1. 拆解卡片的“取消勾选”未在真机完成验证（一次误触按默认全选创建了 4 个阶段）；UI 与写入逻辑支持按选择创建。
2. “拒绝拆解后不反复催促”未单独造场景验证；提示词未要求模型追踪拒绝状态。
3. 多个相似目标时主动澄清依赖模型；客户端只做了同名目标的创建拦截与“修改目标未定位”提示。
4. 真实模型中一次拆解请求返回无法识别的响应格式（已正确显示失败、无写入），重试后成功。
5. 连续重复同一句话时模型会拒绝继续展开，属于模型行为，不产生任何写入。
6. 目标修改暂不支持改层级/父目标（避免破坏树与历史），也不支持在卡片内直接编辑层级。
7. ADB 只能输入英文，录屏中补充文字为英文。

## 八、下一步

- 拆解建议支持“部分创建 + 后续补充”，并记住被拒绝的拆解。
- 变更卡片支持逐字段选择（只应用标题或只应用期限）。
- 目标名称近似匹配（同义标题）时主动提示“是否修改该目标”。
