# 0.25.2.1 — 未完成问题与限制

1. **真机路径 / 新版截图待补**：之前的手机解锁交接被用户停止。遵照停止指示，本轮没有再操作手机；`connectedQaAndroidTest`、建议→handoff→多轮→草案编辑/确认→Today/Trajectory→重启的 0.25.2.1 真机路径，以及新版屏幕截图均未完成。旧版画面仍可看 [0.25.2 顾问对话截图](../mengya-0.25.2/screenshots/03-advisor-discussion-qa.png)，但不伪造新版截图或声称真机验收通过。
2. **真实外部模型体验待验**：本轮真实供应商模型调用数为 0。ScriptedAdvisorEngine、QA FakeAdvisorEngine、FakeTransport 只验证代码路径/调用数/协议与失败处理，不能证明真实模型质量、服务端接收/取消语义或线上延迟。
3. **恢复等待延迟**：继续沿用现有 RestoreWriteBarrier，HTTP 请求期间持有写许可；长请求会延迟 Restore。协程取消无法证明服务端撤回已收到的请求；本轮没有扩展恢复框架。
4. **显式话题切换仍使用短语识别**：已覆盖“换个话题/聊个别的/不谈刚才那个”等常见表达，但隐式或未覆盖的切换仍可能延续当前 Insight 线程。尚未引入语义分类器/新会话模型。
5. **孤儿旧草案来源不可恢复**：新草案有稳定 Insight pointer；旧版 JSON 数组会尝试从关联消息恢复。如果旧草案与相关消息都缺失/损坏，历史来源无法重建；普通旧版无 Insight 草案仍可通过顾问确认流程兼容。
6. **早期 dataVersion 不透明**：0.25.2 及更早版本只保存不可拆分的哈希，无法准确区分来源事实变化与窗口变化；旧报告显示保守说明，不声称用户改过事实。
7. **继承限制**：Care 的数据库 claim 与 Android NotificationManager.post 不是同一事务；SAF 恢复选择/预览/确认流程仍缺独立真机验收；同 endpoint 恢复时是否要求重新授权仍需产品决策；自由文本诊断拦截是保守规则而非完整语义分类。
