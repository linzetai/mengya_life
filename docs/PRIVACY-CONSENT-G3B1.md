# Gate 3B-1 · 持续授权与隐私说明

版本：`0.7.0-g3b1`（versionCode 7）  
授权文案版本：`1`；数据类别版本：`1`  
存储：DataStore `mengya_consent`（QA：`mengya_consent_qa`）

## 1. 产品决策

采用**首次一次性授权、后续持续生效、按需使用个人成长数据**。

首次启用顾问时，用户必须阅读并确认：

- AI 可以按需使用目标、进展、日记、历史对话；
- 这些信息可能发送到用户配置的第三方模型服务；
- 不会把整个本地数据库一次性发送；
- 授权长期有效，可在「设置 → AI 与隐私」按类别关闭或整体撤回；
- AI 只有建议权，业务数据修改仍需用户确认；
- 关闭只影响未来请求，不删除本地数据；
- 已经发送给第三方的数据无法从对方撤回。

同意后，后续对话**不再逐次弹窗**。Gate 3A 的「每次发送前确认目标摘要」已删除。

## 2. 授权状态

`AiConsentState` 持久化：

| 字段 | 含义 |
|---|---|
| `granted` | 是否已授权 |
| `textVersion` | 授权文案版本；不一致必须重新授权 |
| `categoriesVersion` | 类别版本；新增敏感类别时不一致，必须重新授权 |
| `grantedAt` | 授权时间 |
| `recipient` | 数据接收服务（规范化 endpoint） |
| `categories` | 已允许的类别集合 |
| `epoch` | 授权代次；每次变更 +1 |

默认状态为**未授权**。Gate 3A 用户没有该文件，因此升级后不会自动视为同意；真机已验证升级后出现首次授权页。

## 3. 数据类别

| 类别 | 内容 |
|---|---|
| `GOALS` | 长期目标、阶段目标、短期行动 |
| `PROGRESS` | 进展记录、数值、单位 |
| `JOURNAL` | 日记标题与正文摘录 |
| `CONVERSATION` | 历史顾问消息 |

首次同意时四类全部允许；之后每类独立开关。

- 关闭某类：未来请求不读取、不发送该类；本地数据保留。
- 新类别（未来版本）：不在旧 `categories` 集合中，默认关闭；同时 `categoriesVersion` 不一致会要求重新授权，不会自动沿用旧同意。
- 更换 endpoint：`recipient` 不一致，授权立即失效，顾问页要求确认新的接收方；确认后 `epoch + 1`。

## 4. context epoch 与历史隔离

每次授权、类别变更、撤回、接收方变更都会 `epoch + 1`。

- 每条 `advisor_messages` 保存 `context_epoch` 与 `sources_json`；
- 新请求只把 `context_epoch == 当前 epoch` 且状态为 SENT 的助手消息作为历史；
- 因此关闭 `JOURNAL` 后，之前由日记生成的回答不会作为历史再次发送；
- 关闭 `GOALS/PROGRESS` 同理；关闭 `CONVERSATION` 完全不发送历史；
- 撤回授权后不读取、不发送任何类别；
- 更换接收方后旧 epoch 消息不会发给新服务；
- 旧聊天仍在本机可见，不删除。

严格策略：任何授权变化都会让旧 epoch 不再进入新请求（比只过滤敏感类别更保守）。这不是删除，只是不发送。

## 5. 竞态处理

- 发送前捕获 `consent.epoch`；
- ViewModel 监听授权状态；请求进行中若 epoch 变化或授权失效，立即取消请求；
- 取消保存 `CANCELLED`，不保存伪造回复；
- 引擎返回后再次校验 epoch/接收方，变化则保存 `CANCELLED` 并丢弃回复内容。

## 6. 设置页

「AI 与隐私」显示：

- 状态：已授权 / 未授权 / 需重新授权；
- 数据接收服务；
- 授权时间；
- 四类数据开关；
- 撤回全部授权（二次确认）；
- 说明：只影响未来请求、不删除本地数据、无法撤回已发送数据。

关闭授权不会删除日记、目标、进展或聊天记录；代码中没有此类删除路径。

## 7. 安全边界

- 授权标记只含布尔/时间/endpoint/类别/epoch，不含 API Key；
- API Key 仍是 Android Keystore AES/GCM 密文 + DataStore，与 Gate 3A 相同；
- 来源日志只保存引用（类型、记录 ID、标题/短标签），不保存完整正文副本、请求体或 Key；
- 草案表只保存 AI 生成的草案 JSON，不写 `goals`/`goal_checkins`；
- 第三方模型服务仍可能记录请求；其留存政策不在应用控制内。

## 8. 已验证

- 首次授权页、拒绝不发数据、同意后进入对话；
- G3A 升级后未自动授权；
- 四类开关独立关闭；
- 关闭日记后新请求无日记来源；
- 关闭目标后无目标/进展来源；
- 撤回后回到授权页，消息/目标/日记数量不变；
- 更换 endpoint 后要求重新授权；
- 旧 epoch 历史不进入新请求（JVM 单测）；真机 DB epoch 递增。
