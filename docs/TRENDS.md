# 真实进展趋势：计算与展示说明（Mengya Life · Gate 2C）

> 实现：`domain/goals/GoalTrends.kt`（纯函数）、`GoalRepository.buildTrends`（数据整形）、
> `ui/components/Charts.kt`（Canvas 绘制）、`ui/screens/GoalSheets.kt`（进展历史）、
> `ui/screens/TrendsScreen.kt`（趋势页真实区）

---

## 1. 数据来源（唯一）

趋势只读取 `goal_checkins` 表里 **用户手动填写** 的数值：

```sql
SELECT * FROM goal_checkins ORDER BY recorded_at ASC, id ASC
```

- `source` 字段当前固定为 `manual`，界面上明确显示
  「数据来源：你手动记录的进展」。
- **不读取**日记正文、演示数据、系统健康数据或任何推断结果。
- 没有「根据文字自动打分」的逻辑，也没有「人生整体评分」。

---

## 2. 过滤规则

一条记录只有在满足以下条件时才进入趋势：

1. `metric_value IS NOT NULL`；
2. `metric_value` 是**有限数**（`Double.isFinite()`）；
3. 记录关联的 `goal_id` 仍存在于 `goals` 表（外键级联删除后不会留下孤儿）。

NaN / Infinity 属于历史脏数据或外部写入；它们会被静默丢弃，
不画进图、也不参与任何统计。新写入在仓库层就会被拒绝（见 §7）。

---

## 3. 分组：不同单位绝不混画

按 **目标 id + 单位** 分组：

```text
目标 A, 单位 "kg"   → 序列 1
目标 A, 单位 "min"  → 序列 2   // 同一目标，但单位不同
目标 B, 单位 "score" → 序列 3
```

- 单位先 `trim()`；空串 / null 统一显示为「无单位」；
- 不同单位**不做换算**（不做「kg → 斤」「分钟 → 小时」）；
- 不把多个单位合成一个「综合分」；
- 每条序列内按 `recorded_at` 升序，同一时刻按 `id` 升序，保证稳定。

---

## 4. 横轴与纵轴

| 轴 | 取值 |
|---|---|
| 横轴 | 真实记录时间 `recorded_at`（Epoch 毫秒），线性映射；**不是「第 N 次记录」** |
| 纵轴 | 该单位的真实指标值 `metric_value` |

- 纵轴范围 = `[min, max]` 上下各留 15% 余量；若所有值相等，则以该值为中心、
  用 `max(|value| × 10%, 1.0)` 作为展开量，避免线贴在边缘。
- 横轴两端显示真实日期（同年 `M月d日`，跨年 `yy年M月d日`）；
- 每个数据点在纵轴上精确落位；下方「数据点明细」逐条列出
  `完整时间 + 数值 + 单位`，最多展示最近 8 条（历史列表仍保留全部记录）。

---

## 5. 四种状态

| 数据情况 | 展示 |
|---|---|
| **0 条数值记录** | 空状态：「还没有数值记录，无法绘制趋势」；说明数值是选填项；不画任何线 |
| **1 条数值记录** | 只画一个点（带淡色光晕），并写明「只有 1 条数值记录，无法判断趋势」；**不连线** |
| **≥2 条、同一单位** | 折线 + 每个点 + 浅色面积；说明「横轴是真实记录时间，纵轴是指标值」 |
| **≥2 条、多个单位** | 每个单位各一张图，并额外说明「不同单位分开绘制，不做换算」 |

趋势页顶部要求至少 1 条数值记录才显示卡片；没有时显示空状态。

---

## 6. 界面位置

### 6.1 目标 → 进展历史（逐目标）

底部面板顺序：

1. 「数值趋势」标题 + 数据来源说明；
2. 每个单位一张图（`MetricTrendChart`）；
3. 单点 / 多点说明；
4. 数据点明细（时间 + 值 + 单位）；
5. 多单位分隔说明；
6. 「进展记录（按时间倒序）」原始列表（文字 + 数值），可与图逐项对照。

### 6.2 趋势页（跨目标）

1. 卡片「我的数值进展」，badge「真实记录」；
2. 只显示**最近 3 组**（按最近记录时间倒序），每组 = 目标 + 单位；
3. 每组展示最近值、记录数、图、点明细、来源；
4. 下方是「演示区（非真实数据）」，保留原有演示图/分数/摘要，并继续标注「演示」。

演示区与真实区之间没有数据共享；演示数据不会进入 `goal_checkins`。

---

## 7. 非法数值的拦截

三层防线：

1. **界面**：输入非数字 / NaN / Infinity 时给出错误，不关闭面板；
2. **View 层**：`GoalRules.parseMetric` 只返回有限数；
3. **仓库层**（最终闸门）：`GoalRepository.addCheckin` 调用
   `GoalRules.validateMetricValue` 与 `validateUnit`，非法值直接返回
   `GoalResult.Error`，**不会写库**。

允许范围：`|value| ≤ 1,000,000,000`，单位长度 ≤ 16 字。
JVM 测试与真机测试都覆盖了 `NaN`、`Infinity`、`-Infinity`、`1e999`。

---

## 8. 图表实现

- 复用项目已有的 Compose `Canvas`（`ui/components/Charts.kt`），
  **没有引入任何图表库**；
- 网格、折线、面积、点全部自绘；
- 单点只画点，不构造路径；
- x 坐标按真实时间戳比例映射，因此记录间隔不均匀时，
  点在横轴上的间距也是不均匀的（符合真实时间语义）。

---

## 9. 已知限制

1. 单位是自由文本，`kg` 与 `KG` 会被当成两个单位（不做大小写归一）；
2. 不提供缩放、平移、区间筛选；
3. 数值只在记录时填写，不能事后补录或修改（本轮不做编辑进展）；
4. 记录跨时区时，时间轴按设备当前时区显示日期，但排序与算术使用 UTC 毫秒；
5. 趋势页最多展示最近 3 组，更多数据可在各目标的进展历史里查看。
